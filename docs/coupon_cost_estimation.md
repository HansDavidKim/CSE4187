# 쿠폰 발송 요청당 예상 비용

`estimate_coupon_costs()`는 한 과거 코호트의 완료된 발송 요청을 집계해 한 정책 결정시점의 전체 고객에게 공통 비용표를 제공한다. 결과의 `cost_inputs`를 `cost_metadata`와 함께 정책 탐색에 전달한다. 단일 Retention 호출은 호출자가 해당 정책의 정확한 후보 키로 표를 선택한다. 고객별 적용 수준과 정확한 수치는 `audit["customers"]`의 그룹을 `audit["applied"]`에 연결해 조회한다. 반환 표와 감사 보고서는 조회마다 독립 사본이다.

## 입력 근거

`EXPOSURE_COLUMNS`는 내부 정규화 입력이다. 실제 배정 원장과 발송 요청 원장, 실행·청구 기록으로부터 작성해야 한다. 한 행은 한 고객의 한 배정이며 Control도 포함한다. 현재 지원하는 계약은 Treatment가 배정 시각에 10% 쿠폰을 한 번 요청하고 Control은 요청하지 않는 방식이다. 기준시각에 알 수 있는 KIT39 snapshot, 실제 고객과 주문·쿠폰·결제시각에 대응하는 `ORDER_COLUMNS`의 주문 상품 행, 관측 범위와 과금 계약을 선언한 `HistoricalCohort`를 함께 전달한다. 실패 요금이 허용되더라도 실제 기록한 금액만 사용한다. 전체 창이 닫히고 사용·과금이 확정돼야 한다. 검열 또는 미완료 행이 있으면 코호트 전체를 거절한다.

정규화할 때 `policy_id`는 검증된 10% 쿠폰 정책 선언과 연결한다. 생산자의 `build_experiment_log()`는 실제 발급 쿠폰에서 `discount_rate`를 읽는다. 성공 행에는 0.1이 필수이며, Control과 발송 실패 행에는 생산자의 NULL을 그대로 전달할 수 있다. 기존 정규화 표가 미발송 행에도 정책 규격 0.1을 기록했다면 이 입력도 허용한다. 할인율만으로 발급 또는 사용을 판정할 수 없다.

학습 Feature, 노출 원장, 평가 Feature의 원본 금액 단위는 정확한 십진수로 같아야 한다. SHA는 공급한 문맥 간 일관성을 검사하는 데 사용한다. 원천 파일의 체크섬 검증, 빠짐없는 배정·청구 원장 확보, 고객 ID의 모집단 간 대응은 공급자의 책임이다. 개발 고객 명부가 있다면 `development_features`로 제공한다. 개발 명부 미제공 여부는 감사표에 남는다. 서로 다른 ID가 같은 사람을 가리키는 경우까지 탐지할 수는 없다.

## 추정과 반올림

요청 수 N, 사용 건수 R, 실제 과금 합 S, 실제 사용 할인액 합 D로 세 항 S/N, R/N, D/R을 구한다. 미발송 Control은 분모에서 빠지고 실패한 요청과 실패 과금은 남는다. `purchase_count_30d_threshold`를 생략하면 전체 평균만 사용한다. 지정하면 직전 30일 구매 횟수가 기준 이상인 고객과 미만인 고객을 나누며, 허용된 결측값은 별도 집단으로 둔다. 최소 요청 수와 최소 사용 건수는 호출자가 지정한다. 각 성분별로 고객군 표본이 부족하면 전체 평균을 사용하고, 전체 표본도 부족하면 비용표 제공을 보류한다. 서로 다른 수준을 결합한 추정치는 감사표에서 식별할 수 있다.

금액은 원천 minor 단위 개수다. 정확한 합계와 기약분수를 보존하고 세 성분을 각자 지정한 자릿수에서 올림한다. 발송비 자릿수와 확률·조건부 할인액 자릿수 합이 모두 Budget 정밀도(최대 9자리) 이하여야 한다. 이 방식은 정확한 추정식 대비 출력 축소를 방지한다. 실제 집행액은 달라질 수 있다.

## 실제 성능 검증 계획

정밀도에 따른 오차는 `audit["applied"][그룹]["expected_cost"]`의 `exact`, `output`, `error`에서 비교한다. 예를 들어 사용 확률 1/1,000, 사용 조건부 할인액 1,000억 minor, 정확한 요청당 발송비 1.999 minor인 경우 발송비를 소수 2자리로 올림하면 2 minor가 된다. 확률을 소수 3자리로 출력할 때 총 오차는 +0.001 minor이고, 0자리로 출력하면 확률이 1이 되어 총 오차가 +99,900,000,000.001 minor로 커진다. 운영 정밀도는 별도 완료 코호트에서 오차와 예산 영향을 비교한 뒤 선택한다.

개발 코호트에서 전체 평균과 고정 집단 평균, 표본 수 기준을 비교한 뒤 규칙과 정밀도를 동결한다. 별도의 완료 평가 코호트에서 실제 요청을 분모로 사용 확률의 Brier score, calibration 및 집단별 편향을 계산한다. 사용 조건부 할인액은 실제 사용자만 대상으로 MAE와 평균 편향을 측정한다. 요청당 총비용은 실패 과금을 포함해 고객별 오차와 집단별 총액 오차를 비교한다. 각 예산의 실제 집행 기록으로 예상 지출 대비 차이와 초과 빈도·금액을 집계한다. 요청하지 않은 고객의 가상 실현 비용은 미관측으로 유지한다. seed43 기준시각 이후의 사용·할인 정보는 해당 고객의 발송 전 추정에 사용할 수 없다.
