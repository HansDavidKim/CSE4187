# 28일 구매 Uplift 모델링 계획

10% 쿠폰을 한 번 발송하도록 배정했을 때 고객의 향후 28일 구매 확률이 얼마나 달라지는지 추정한다. 고객별 점수는 같은 사전 특성을 가진 고객의 조건부 평균 효과 추정치다.

## 1. 실험과 학습 행

- 기준 시각 `t0`는 서울 월요일 00시의 배정 시각이며 SQLite에는 UTC로 저장한다.
- 직전 28일에 세션을 시작한 적격 고객을 한 명당 한 행으로 둔다. 처치 `T`는 고정 1:1 무작위 배정이며, 발송 실패와 미사용 고객도 원래 배정군에 둔다.
- `Y = 1 − experiment_log.factual_no_order`로 정의한다. 배정 후 `[t0, t0 + 28일)`에 주문이 있으면 1, 관측을 마쳤고 주문이 없으면 0이다. 관측이 덜 끝난 고객의 정답은 NULL로 보존한다. 방문 기준 이탈 라벨은 별개다.

## 2. 어떤 피처를 재사용하는가

시뮬레이터 v5 설계서 4·12–15·21절과 `simulator/src/simulate/v4/{features,behavior_features,storage}.py`를 기준으로 한다. SQLite의 `feature_registry`와 `features`에서 KIT39 v3의 순서와 값을 읽는다. 기본 실험의 모델 입력은 아래 36개다. 개별 컬럼과 산식은 [피처 사전](feature.md)에 있다.

| 번호 | 모델에 쓰는 정보 | 기준 |
| --- | --- | --- |
| F01–08 | 방문·구매 최근성, 관측 기간, 세션·조회·주문 수, 결제액과 객단가 | 전체 과거 이력 또는 최근 30일 |
| F09–17 | 완료 세션 체류·조회·주문, 구매·방문 간격, 구매 상품 종류와 수량 | 완료 세션, 구매 이력, 최근 90일 방문 간격 |
| F18–24 | 장바구니 수량·상품 수·금액, 마지막 완료 세션의 조회 가격과 시작 시각·요일 | 배정 직전 상태 |
| F28–32 | 주문 수·결제액·객단가·상품 수·구매 수량의 변화 | 최근 30일에서 직전 30일 값을 뺌 |
| F33–39 | 리뷰 수·별점·최근성, 비구매 세션의 담기·제거, 5점 미만 리뷰 비율 | 도착한 리뷰와 완료된 세션 |

F25–27은 과거 쿠폰 사용 횟수·최근성·할인액이다. 기본 실험에는 사전 쿠폰 발송이 없어 입력에서 제외한다. 공통 데이터셋은 컬럼 순서와 NULL을 유지한다. 히스토그램 부스팅은 학습 분할에서 중앙값과 결측 지표를 만들며, 한 군의 결과가 단일 값이면 그 군의 관측 구매율을 사용한다. ID·배정·쿠폰 사용 결과·미래 행동·잠재 반응 유형은 X에 넣지 않는다.

## 3. 구현 순서

1. 저장소 공용 `common/simulator_features.py`에서 읽기 전용 SQLite 연결과 등록 피처 조회를 제공한다. Uplift에서는 고객·배정 시각·스냅샷·데이터셋이 일치하는 실험 기록을 연결한다. 기존 원시 로그 입력과 합성 예제도 지원한다.
2. 정답이 있는 고객을 배정군별로 층화해 학습 70%, 평가 30%로 한 번 나눈다. 세 모델이 같은 분할을 쓴다. H의 설정 선택에는 학습 고객 내부의 검증 분할만 쓴다.
3. T는 두 군에서 각각 구매 확률을 학습해 차이를 구한다. X는 반대 군의 구매 확률로 만든 가상 효과를 각 군에서 회귀하고 배정 확률로 합친다. H는 결과 오차와 가상 효과 오차를 함께 줄이도록 두 함수를 학습하고 검증 손실로 가중치와 반복 횟수를 고른다.
4. 평가 고객으로 Qini 계수·곡선과 평균 예측 효과를 비교한다. 전체 적격 고객의 모델별 구매 확률과 점수를 CSV로 내보내고 각 행에 학습·평가·미관측 여부를 표시한다.
5. 프로젝트의 세그먼트 예시 기준을 적용한다. 음의 점수는 Sleeping Dogs, 나머지 중 미발송 구매확률이 0.5 이상이면 Sure Things, 그 외에서 점수가 0.05를 넘으면 Persuadables, 나머지는 Lost Causes다. 이 분류는 타기팅 규칙이며 실측 반응 유형을 뜻하지 않는다.

## 4. 간단한 검증

소수 고객으로 시뮬레이터의 generate → features를 실행한다. SQLite에서 읽은 피처와 28일 주문 정답을 확인하고, 세 모델의 CSV에서 고객 수·평가 분할·확률 범위·점수 차이를 점검한다. 소규모 결과는 입출력 검증에 쓰고 모델 우열 판단은 별도 대규모 실험에서 진행한다. 재현 명령과 출력 경로는 [실행 안내](readme.md)에 있다.
